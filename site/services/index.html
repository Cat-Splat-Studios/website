Technology case study

Cat Splat Engine

A C++ runtime and toolchain developed together: author a scene, run it, and keep iterating.

  1. 01 · AuthorA dockable editor for scenes, components and game UI.
  2. 02 · RunA standalone player sharing the engine's scene format.
  3. 03 · ValidateA headless tool for checking project content.

Working foundations

The C++17 runtime uses OpenGL 3.3, with physically based rendering, cascaded shadows and post-processing. Scene editing, serialization and play-in-editor support the day-to-day development loop.

Physics, scripting and audio sit behind separate interfaces. Backends include Jolt and PhysX for physics, Lua for scripting and miniaudio for audio.

What this work demonstrates

Rendering and tools designed as parts of the same workflow, with replaceable subsystems and content checks. It is the foundation for our low-level engineering work.

An actively developed engine, not a released game platform. Windows is the current supported target; wider platform support is planned.

Explore the source →

Future direction

Planned work, separate from the capabilities available today. No delivery dates are announced.

  • Swappable rendering: a modern Vulkan backend with OpenGL retained as a compatibility option.
  • Ray tracing: explore hardware-accelerated lighting after the renderer foundations are in place.
  • More platforms: expand runtime support and packaging, including mobile targets.
  • Peer-to-peer rollback: investigate networking around Jolt, including state restoration and determinism testing across supported targets.
